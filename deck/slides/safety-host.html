Making pi safe

When you are watching: a host sandbox

pi-sandbox blocks

  • Reads anywhere in your home folder except the project
  • Writes outside the project, and to .env and keys at any depth
  • .git/hooks and .git/config, so no hook runs later on your machine
  • Pi’s own config, skills and MCP files, so nothing persists
  • Any domain not on the list: PyPI, npm and GitHub only

Upside: a blocked path or domain asks you, much like a Claude Code permission prompt.

Trade-off: pi and its extensions run outside it. I keep extensions few and known.

# install once, pinned

pi install npm:pi-sandbox@0.7.2

# then, inside any pi session:

/sandbox    # show the policy

/sandbox-allow domain pypi.org

# ~/.pi/agent/sandbox.json, in part

"denyRead": ["/Users", "/Volumes"],

"allowRead": [".", "~/.gitconfig", …],

"allowWrite": [".", "/tmp", "~/.cache/uv"],

"denyWrite": [".env", "**/.env", "*.pem",

  ".git/hooks", ".pi/extensions", …]

pi-sandbox 0.7.2 by carderne, source read in full. macOS sandbox-exec for bash, a path check for read, write and edit.

No. 10

For attended work I run pi on the host with pi-sandbox. Installing it is one pinned command, and from then on it loads with every pi session; slash sandbox shows the live policy, and slash sandbox-allow adds a domain or path without waiting for a block. It wraps every bash command in macOS sandbox-exec and checks the paths of pi's read, write and edit tools. My global config denies all of /Users and then re-allows the project and a handful of things tools need, like git config and uv's folders. It blocks writes to secrets at any depth, to the git hooks and config, so the agent cannot plant a hook that runs later on your own machine, and to pi's own config, skills and MCP files, so nothing it writes can come back in a later session. Network is an allowlist: PyPI, npm, GitHub. When something is blocked it asks you to allow it for the session, the project or globally, which is the closest thing to Claude Code's permission prompts. The trade-off: the sandbox wraps the tools, not pi itself. Pi and every extension run with your full permissions, so I keep extensions few and read every one before installing it. And I read the sandbox itself: its runtime drops some upstream protections, which is why .git/hooks and friends are spelled out here.
