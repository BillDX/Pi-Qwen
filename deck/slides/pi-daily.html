Pi as a coding environment

What it is like to drive

Upside

Fast and quiet

Four tools and a two-thousand-token prompt. It starts at once and stays out of the way.

Upside

Steer while it works

Enter queues a steering note, Alt+Enter a follow-up, Escape stops the turn.

Upside

Sessions are a tree

/tree jumps back, /fork branches, /compact summarises when you choose.

Trade-off

No permission prompts

It edits and runs commands straight away. Only the guards and sandbox you add will ask.

Trade-off

No plan mode or subagents out of the box

Nor a to-do list. Example extensions add all three on demand though; I use a PLAN.md.

Trade-off

Slower turns

A one-line fix takes a minute or two. Queue the next task rather than watching.

No. 07

Day to day, three things feel better than you might expect. It is fast to start and quiet: four tools, a prompt of about two thousand tokens, and a fullscreen terminal UI since version one. You can steer it while it works: Enter queues a note it reads after the current step, Alt+Enter queues a follow-up for when it finishes, Escape stops. And sessions are a tree: you can jump back, branch from an earlier message, and compact when you decide to, not when it decides to. Three things you will miss from Claude Code. There are no permission prompts; pi edits files and runs commands straight away, and only what you add will ask. There is no plan mode, no to-do tool and no subagents built in; pi ships example extensions for all three, and I mostly use a PLAN.md file and a couple of prompt templates instead. And turns are slower; a one-line fix takes a minute or two, so the habit to build is queueing the next task, not watching the current one.
