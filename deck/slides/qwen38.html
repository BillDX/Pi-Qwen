Takeaway:  It feels like Opus 4.6.   In 16GB.   Which is amazing.

What makes this particular model good for local coding? It is small enough: 27 billion dense parameters under Apache 2.0, sixteen gigabytes at 4-bit. Its long context is cheap: only sixteen of its sixty-four layers use full attention, the rest use a linear-attention design, so 262 thousand tokens of context does not eat your memory. It was trained with multi-token prediction heads, which is what MTPLX uses to draft ahead. Tool calling is reliable: in my own test every one of thirty-six tool calls was well formed. And it holds up at 4-bit: fourteen of fifteen coding tasks through pi on LM Studio, fifteen of fifteen on MTPLX. On Qwen's own card it beats the Opus 4.6 of earlier this year on SWE-bench Pro and LiveCodeBench, and trails it on Terminal-Bench; those are vendor numbers, so weigh them accordingly. Simon Willison picked pi to try it, for the same reason I did: a short system prompt suits a small model. The trade-off: it thinks at length. Its default reasoning effort is extra high, which Willison found produced spectacular over-thinking; I run it at medium.
