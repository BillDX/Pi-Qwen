16 GB at 4-bit

What makes this particular model good for local coding? It is small enough: 27 billion dense parameters under Apache 2.0, sixteen gigabytes of weights at 4-bit, which runs on a 32 gigabyte Mac with a shorter context. Its long context is cheap: only sixteen of its sixty-four layers use full attention, the rest use a linear-attention design, so its context cache is about four times smaller than usual, though a full 262 thousand tokens still adds about sixteen gigabytes. It was trained with a multi-token prediction layer, which is what MTPLX uses to draft ahead. Tool calling is reliable: in my own test every one of thirty-six tool calls was well formed. And it holds up at 4-bit: in Quesma's test the 4-bit build solved the same 63 of 89 Terminal-Bench tasks as full precision. In my own runs the 4-bit passed fourteen of fifteen tasks and the 8-bit twelve, its misses all time-outs; MTPLX's 4-bit build passed all fifteen. On Qwen's own card it beats the Opus 4.6 of earlier this year on SWE-bench Pro, scored on Qwen's corrected task set, and on LiveCodeBench, and trails it on Terminal-Bench; those are vendor numbers, so weigh them accordingly. Simon Willison picked pi to try it, for the same reason I did: a short system prompt suits a small model. The trade-off: it thinks at length. Its default reasoning effort is extra high, which Willison found produced spectacular over-thinking; I run it at medium.
