No. 16

The second practice is managing the window. On Claude Code you rarely think about context; here you must, and the reason is reading speed, not memory. Qwen3.8 supports 262 thousand tokens and my laptop has room for it, but a cold read of a 48 thousand token prompt took over nine minutes, so I cap pi at 131 thousand, which means it compacts automatically near 115 thousand. Most turns are cheap, because the server reuses the cached start of the prompt; in my test runs 87 percent of prompt tokens came from cache. Speed is the other reason. In my MTPLX logs, writing runs at about twenty tokens a second under 8 thousand tokens of context, twelve to thirteen between 8 and 64 thousand, and under ten past 64 thousand, because every step re-reads a longer cache. The habits protect that cache and keep the window small. Compact on purpose, at forty to sixty thousand, after the plan file is up to date. One task per session. Never switch models mid-session, because each model keeps its own cache. Search with ripgrep and read line ranges rather than whole files, and keep tool output short. And the rule of thumb: if the window feels too small, the task is too big.
