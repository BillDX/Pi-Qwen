FANS GO 'WHIRRR'

Same model, two engines. LM Studio is where I started and where I would tell you to start: one app with a model browser and an OpenAI-compatible server, and its MLX build of Qwen3.8 at 4-bit is sixteen gigabytes. MTPLX is a newer runtime that uses the model's own multi-token-prediction heads to draft a few tokens ahead and check them in one pass. On predictable code that doubles the writing speed. On varied prose it adds about fifteen percent. And it does nothing for reading the prompt, which is the part you feel most with a local model. Through pi on five real coding tasks, three runs each, MTPLX passed all fifteen and took thirty minutes against thirty-six, so about a quarter faster in practice, not twice. These are short-context numbers: in long sessions past 64 thousand tokens of context, MTPLX on this machine writes at about ten tokens a second, and heat costs more on top. So my default is MTPLX, through the pi-mtplx extension, with LM Studio as the fallback. One warning: read what installers do. The MTPLX installer added a passwordless sudo rule, which I removed.
